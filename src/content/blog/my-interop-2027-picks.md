The nomination phase for interop 2027 is now over yielding a final list of [100 features](https://github.com/web-platform-tests/interop/issues?q=is%3Aissue+state%3Aopen+sort%3Areactions-desc+label%3Afocus-area-proposal) that people want to be included in Interop 2027.

[Jake from Firefox](https://indieweb.social/@jaffathecake@mastodon.social) created a tool called ["2027 Web Platform Feature Ranking"](https://interop-rank.fxdx.dev/) that allows people to select their favorites from this long list and produce a personal selection sub-list.

Here is my list:

<ol class="interop">

<li><a href="https://github.com/web-platform-tests/interop/issues/1343">CSS if() function</a>

<em>An inline conditional value that returns a value based on a set of conditions.</em>

Why I chose this feature: this enables so much cool stuff but especially: the ability to evaluate a style query against an indivual item (not evaluating a container).
</li>

<li><a href="https://github.com/web-platform-tests/interop/issues/1357">CSS @function</a>

<em>Defines custom functions that take arguments and return a CSS value.</em>

Why I chose this feature: the ability to write a (complicated) bunch of code and be able to call that code is a
</li>

<li><a href="https://github.com/web-platform-tests/interop/issues/1452">CSS ident() function</a>

<em>Builds an identifier from strings, integers, and other identifiers, such as view-⁠transition-⁠name: ident("item-⁠" sibling-⁠index()).</em>

Why I chose this feature:
</li>

<li><a href="https://github.com/web-platform-tests/interop/issues/1371">CSS border-⁠shape property</a>

<em>Sets the geometry of the border box to a fully custom shape, changing the shape of borders, outlines, and shadows.</em>

Why I chose this feature:
</li>

<li><a href="https://github.com/web-platform-tests/interop/issues/1393">Customizable/stylable &lt;select&gt;</a>

<em>Customize the button, selected option, picker, and options with CSS.</em>

Why I chose this feature:
</li>

<li><a href="https://github.com/web-platform-tests/interop/issues/1363">CSS anchored container queries</a>

<em>@container anchored(fallback: …) applies styles based on which position fallback an anchor-positioned element is using.</em>

Why I chose this feature:
</li>

<li><a href="https://github.com/web-platform-tests/interop/issues/1344">CSS var() in size container queries</a>

<em>Such as @container (width >= var(-⁠-⁠min-⁠width)).</em>

Why I chose this feature:
</li>

<li><a href="https://github.com/web-platform-tests/interop/issues/1354">CSS random() function</a>

<em>Chooses a random numeric value within a specified range.</em>

Why I chose this feature:
</li>

<li><a href="https://github.com/web-platform-tests/interop/issues/1403">CSS random-⁠item() function</a>

<em>Picks a random item from a list of values.</em>

Why I chose this feature:
</li>


<li><a href="https://github.com/web-platform-tests/interop/issues/1444">CSS margin-⁠trim</a>

<em>Removes the margins of child elements when they meet the edges of the container.</em>

Why I chose this feature:
</li>

<li><a href="https://github.com/web-platform-tests/interop/issues/1453">CSS inherit() function</a>

<em>Like var(), but uses the parent element's value of the custom property.</em>

Why I chose this feature:
</li>

<li><a href="https://github.com/web-platform-tests/interop/issues/1364">CSS container scroll-state queries</a>

<em>The @container scroll-⁠state(...) at-rule applies styles based on the sticky positioning, snapped, and scrollable state of the container.</em>

Why I chose this feature:
</li>
</ol>
